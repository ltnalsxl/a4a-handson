누구나 AI 에이전트를 만들도록 돕는
AI 에이전트를 직접 만듭니다

A4A(Agent for Agent)는 이름 그대로 “누구나 에이전트를 만들도록 돕는 에이전트”입니다.

구성원이 업무 고충을 말하면, A4A가 인터뷰 → 사내 지식 그라운딩 → 설계 추천 → 담당자 승인을 거쳐 또 다른 에이전트의 제작 패키지(설계서)를 만들어 줍니다.

이 과정에서 여러분은 에이전트 제작의 전 과정을 자연스럽게 익히게 됩니다.

🎯
오늘의 목표: 단순히 “에이전트 하나”를 만드는 게 아니라, “누구나·안전하게 에이전트를 만들도록 돕는 코치(A4A)”를 직접 구축하면서 에이전트 제작의 핵심을 익힙니다.

PART 1 A4A 소개

A4A란 무엇인가: 누구나 에이전트를 만들도록 돕는 에이전트

A4A를 한 문장으로 정의하면 “누구나 AI 에이전트를 만들도록 돕는 AI 에이전트”입니다. 일반 에이전트와 무엇이 다른지부터 명확히 짚고 갑니다.

일반 에이전트: “일하는” 에이전트

  • → 가격 계산, 문서 요약, 특허 검색처럼 하나의 업무를 직접 수행
  • → 결과물 = 그 업무의 산출물
  • → 비유: 완성된 요리

A4A: “도와주는” 에이전트

  • ★ 업무를 수행하지 않고, 다른 에이전트의 설계서를 생성
  • ★ 결과물 = 에이전트 제작 패키지(.docx)
  • ★ 비유: 요리를 가르쳐주는 요리 선생님
💡
만드는 기술(Agent Builder, Copilot Studio)은 똑같습니다. 다른 건 목적이에요. A4A는 “에이전트 제작” 자체를 도와주는 한 단계 위의 에이전트입니다. 그래서 오늘은 “에이전트 만들기를 도와주는 에이전트”를 직접 만드는 실습을 합니다.
왜 이런 걸 만드나: 목표와 배경

A4A가 풀려는 문제

  • 한두 개의 에이전트를 전문가가 만들어주는 것으로는 조직 전체로 확산되지 않습니다
  • 그렇다고 모두가 자유롭게 만들면 품질 저하·보안 사고(방치되는 에이전트, 미검증 외부 도구 사용, 비용 낭비)가 발생합니다
  • A4A는 “누구나 + 제대로 + 안전하게” 에이전트를 만들도록 돕는 가이드이자 가드레일 역할을 합니다
✓
이 교육의 진짜 목표: A4A를 예제로 만들어보며, 여러분이 앞으로 어떤 에이전트든 직접·안전하게 만들 수 있는 역량을 갖추는 것입니다.

PART 2 Agent Builder 핸즈온

A4A Lite 만들기: 실습 개요

M365 Copilot에 내장된 Agent Builder로 코드 한 줄 없이 5~10분 만에 동작하는 “에이전트 제작 코치(A4A Lite)”를 만듭니다. 별도 라이선스·환경 구축이 필요 없는 노코드 선언형 에이전트입니다.

🧭
왜 같은 A4A를 두 도구로 만드나요?: 오늘은 같은 A4A를 두 가지 도구로 만들어 봅니다. PART 2에서는 Agent Builder로 쉽고 빠르게(노코드), PART 3에서는 Copilot Studio로 정교하게(풀버전). 같은 목표를 두 방식으로 구현해보며 “언제 어떤 도구를 쓰는지”를 익히는 것이 목표입니다.

이 실습을 마치면

  • M365 Copilot에서 새 에이전트로 에이전트를 생성할 수 있습니다
  • 안내·지식·기능·추천 프롬프트를 설정할 수 있습니다
  • 사용해 보기 미리보기로 검증하고 만들기 후 공유할 수 있습니다
🧰
준비물: M365 Copilot 라이선스 계정, 웹 브라우저. 접속: 브라우저에서 microsoft365.com/chat 에 접속하거나 Microsoft 365 Copilot 앱을 엽니다.
PART 2 2.1 · 에이전트 생성 진입

에이전트 생성 진입: 새 에이전트

Microsoft 365 Copilot 앱 열기

브라우저에서 microsoft365.com/chat 에 접속하거나 Microsoft 365 Copilot 앱을 엽니다. 좌측 패널에서 에이전트를 펼친 뒤 새 에이전트를 선택합니다.

생성 방식 이해하기: 자연어 설명 vs 구성

처음 화면에서는 만들려는 에이전트를 자연어로 설명해 자동 생성할 수 있습니다. 이번 실습은 정확한 학습을 위해 구성으로 건너뛰기를 눌러 구성 화면에서 각 항목을 직접 입력합니다.

  • 자연어 설명: 만들려는 에이전트를 문장으로 적으면 이름·설명·안내·지식을 자동 생성(빠른 경로)
  • 구성: 이름·안내·지식·기능을 직접 입력(이번 실습 권장)

구성 화면 살펴보기

상단 탭은 구성(직접 설정)과 사용해 보기(미리보기)로 나뉩니다. 우측 상단 만들기 버튼으로 마지막에 생성합니다.

⚠️
예전 문서의 “Create agent”는 현재 새 에이전트로, “Configure/Try it”은 구성/사용해 보기로 한글화되었습니다.

안내(Instructions) 예시, 붙여넣어 사용
## 역할
당신은 사내 구성원의 업무 고충을 듣고, 그 일을 자동화할 수 있는
에이전트를 제안하고 '설계서'를 만들어 주는 설계 코치입니다.

## 진행 순서
1. 인사한 뒤, 아래 4가지를 한 번에 하나씩 순서대로 질문해 파악한다.
   이미 답한 항목은 다시 묻지 않고, 답이 모호하면 한 번만 더 되묻는다.
   (1) 어떤 업무인가요? (업무 이름과 한 줄 설명)
   (2) 얼마나 자주 반복되나요? (매일·주간·월간·비정기)
   (3) 어떤 데이터·문서를 다루나요? 보안 등급은? (공개·내부·대외비)
   (4) 결과물은 어떤 형태로 누구에게 전달되나요?
2. 4가지가 모이면(또는 사용자가 설계서를 요청하면) '설계서 생성'
   도구를 호출해 설계서를 만든다. 도구가 아직 없으면 같은 내용을
   직접 표로 정리해 보여준다.

## 설계서에 담을 내용
- 에이전트 이름과 한 줄 목적
- 추천 플랫폼(Agent Builder 또는 Copilot Studio)과 선정 이유
- 지침(Instructions) 초안
- 필요한 참조 자료(Knowledge Source) 목록
- 테스트 시나리오 3개
- 보안 체크리스트 확인 결과

## 답변 규칙
- 등록된 참조 자료(Security_Rule, Platform_Rule, Legacy_System_Map,
  MarketCase)에 근거해서만 답한다. 자료에 없는 내용은 지어내거나
  웹·일반 상식으로 채우지 않고 "관련 사내 자료가 없습니다"라고 말한다.
- 보안 규정(Security_Rule)과 데이터 등급을 먼저 확인하고, 그 등급에
  맞는 플랫폼(Platform_Rule)만 추천한다.
- 인터뷰 도중에는 해결 팁이나 일반 정보를 늘어놓지 않고 질문에만 집중한다.
- 한 번에 한 가지만, 정중하고 간결한 존댓말로 답한다.
💡
지침을 구체적으로 적을수록 답이 정확해집니다. 특히 분기 질문을 자세히 적어두면 에이전트가 빠뜨리지 않고 인터뷰합니다.

📝지침 (Instructions)

에이전트의 성격·말투·일하는 방식을 정하는 글. 쉽게 말해 “너는 이런 코치야”라고 적어 주는 설명서입니다.

📚참조 자료 (Knowledge)

에이전트가 답할 때 근거로 삼는 자료. 사내 문서를 올려 두면, 추측 대신 그 내용에 맞춰 답합니다.

예: 보안 규정·플랫폼 기준 등 실습 자료 4종

🛠️도구 (Tools)

에이전트가 실제로 ‘무언가를 하게’ 해 주는 기능. 설계서를 만들거나 메일을 보내는 등 행동을 담당합니다.

예: 인터뷰 내용을 받아 설계서를 만드는 ‘설계서 생성’ 도구

💬토픽 (Topics)

정해진 대화 흐름. “이 상황엔 이 순서로 물어봐”처럼 대화 시나리오를 고정하고 싶을 때 씁니다.

예: 업무 고충을 정해진 순서로 묻는 인터뷰 흐름

🔗
이 재료들이 어떻게 알아서 맞물릴까? 핵심은 생성형 오케스트레이션(3.3, 기본 켜짐)입니다. 켜져 있으면 에이전트가 지침·참조 자료·도구·토픽을 상황에 맞게 스스로 골라 동작합니다. 우리가 “이 순서로 이걸 불러라”라고 코드로 연결하지 않습니다. 도구·토픽은 이름·설명을 보고 필요할 때 자동으로 부르고, 입력이 필요하면 사용자에게 직접 되물어 채웁니다. 그래서 도구·토픽의 이름·설명을 명확히 쓰는 것이 가장 중요합니다.
✅
어디까지 하면 동작하나요? 3.1 생성 → 3.2 참조 자료 등록 → 3.7 게시만 해도 목표(인터뷰 → 설계서 제안)가 동작하는 에이전트가 나옵니다. 즉 지침과 참조 자료만으로도 인터뷰하고 설계서를 표로 내놓습니다. 3.4 인터뷰 토픽, 3.5 설계서 도구, 3.6 검토·승인은 “대화 순서를 고정”하거나 “설계서 형식을 매번 똑같이” 하고 싶을 때 더하는 선택(심화) 단계입니다. 시간이 부족하면 3.1·3.2·3.3·3.7만 진행해도 됩니다.

이 실습을 마치면

  • Copilot Studio에서 에이전트를 생성하고 Knowledge 4종을 등록할 수 있습니다
  • 인터뷰용 Topic과 설계서 생성용 Tool(프롬프트/플로우)을 만들 수 있습니다
  • 생성형 오케스트레이션을 이해하고 테스트 후 게시할 수 있습니다

PART 3 3.1 · 에이전트 생성

에이전트 생성

Copilot Studio 접속

브라우저에서 copilotstudio.microsoft.com 에 접속합니다. 홈 화면에 “무엇을 빌드하시겠습니까?”와 에이전트/워크플로 토글, 자연어 입력 상자가 보입니다. 우측 상단 환경은 교육용 환경이 따로 안내되었다면 그 환경을 선택하고, 그렇지 않으면 안내에 따라 주세요.

빈 에이전트로 시작

정확한 학습을 위해 자연어 생성 대신 직접 만듭니다. 좌측 에이전트 아이콘을 눌러 에이전트 페이지로 간 뒤, 우측 상단 + 빈 에이전트 만들기를 누릅니다.

에이전트 이름 지정 팝업이 열리면 에이전트 이름을 입력합니다. 언어·솔루션 등을 직접 지정하려면 에이전트 설정(선택 사항)을 펼쳐 설정한 뒤, 만들기를 누릅니다.

▸ 에이전트 설정(선택 사항) 자세히: 언어·솔루션·전용 솔루션 만들기

에이전트 설정(선택 사항)을 펼치면 아래 항목을 직접 고를 수 있습니다.

  • 언어: 한국어(대한민국) 선택
  • 솔루션: 에이전트가 담길 솔루션. 회사에서 안내한 지정 솔루션이 있으면 그것을 고르고, 없으면 기본 솔루션(Common Data Services Default Solution) 그대로 둬도 됩니다.
  • 스키마 이름: 자동으로 채워집니다(예: cr940_). 그대로 두면 됩니다.

전용 솔루션을 새로 만들고 싶다면 (교육·공유 환경 정리용, 선택):

  1. 좌측 사이드바 맨 아래 …(더 보기) → 살펴보기 → 솔루션을 엽니다.
  2. 상단 + 새 솔루션을 누릅니다.
  3. 오른쪽 패널에서 표시 이름·이름·게시자·버전(기본 1.0.0.0)을 입력하고 만들기. (이 솔루션을 기본으로 쓰려면 선호하는 솔루션으로 설정 체크)
  4. 다시 에이전트를 만들 때 에이전트 설정(선택 사항)의 솔루션 드롭다운에서 방금 만든 솔루션을 고릅니다.
💡
솔루션을 안 만들어도 에이전트는 자동으로 기본 솔루션에 담겨 정상 동작합니다. 전용 솔루션은 정리·이관·배포가 편해지는 선택 사항일 뿐입니다.

기본 정보 입력

PART 3 3.2b · 웹 검색·도구·Work IQ

Overview의 추가 설정: 웹 검색·도구·Work IQ

같은 개요 화면에는 참조 자료 외에도 몇 가지 설정이 더 있습니다. A4A에 맞게 어떻게 둘지 정리합니다.

웹 검색 (Web search) · 이 실습에서는 끄기

에이전트가 공개 웹(Bing)을 검색하게 하는 토글입니다. 이 A4A는 사내 자료에 근거해 판단하는 에이전트라, 외부 웹이 섞이면 사내 기준과 어긋난 답이 나올 수 있어 끕니다. 끄는 위치는 3.3의 설정 → 생성형 AI → 지식 → 웹의 정보 사용입니다(거기서 캡처로 안내).

💬
“무조건 꺼야 하나요? 4종 자료로만 답하나요?” 무조건은 아닙니다. 진짜 가드레일은 지침(“등록된 참조 자료에만 근거”)이고, 웹 검색 끄기는 실습 결과를 일정하게 하려는 안전장치입니다. 참고로 “4종으로만”이라는 뜻은 사실 판단(보안 등급·플랫폼 추천·사례)을 4종에 근거한다는 것이지, 모델이 글을 못 쓴다는 뜻은 아닙니다. 일반 글쓰기·요약 능력은 그대로 쓰되 근거가 필요한 부분만 4종에서 가져옵니다. 일반 웹 정보까지 답하게 하려면 켜도 되지만, 그땐 답이 사내 기준 밖으로 번질 수 있습니다.
🧩
“에이전트 만드는 법(Microsoft Learn 등)을 지식에 넣어야 하지 않나요?” 이 A4A에는 필요 없습니다. 결과물이 설계서(계획서)이지 클릭 따라하기 매뉴얼이 아니거든요. “Agent Builder와 Copilot Studio가 뭔지, 어떻게 다른지, 지침 초안을 어떻게 쓰는지”는 모델이 이미 학습으로 알고 있어 따로 넣지 않아도 됩니다. 정작 모델이 모르는 사내 기준(어떤 보안 등급에 어떤 플랫폼이 되는지·사내 시스템·사례)만 4종 자료로 채우면 됩니다. 그래서 웹 검색을 꺼도 괜찮습니다. 다만 제품의 최신 사용법까지 정확히 답하게 하고 싶다면, 넓은 웹 검색(Bing 전체)을 켜는 대신 Microsoft Learn 같은 특정 웹사이트를 참조 자료로 지정하는 편이 정확합니다(범위가 좁아 덜 새니까요). “외부 지식이 필요 = 웹 검색”이 아니라 “신뢰할 특정 사이트를 지식으로 추가”가 정석입니다.

도구 (Tools)

도구 추가로 에이전트가 실제 작업(설계서 생성, 메일 발송 등)을 하도록 기능을 붙입니다. A4A의 설계서 생성 도구는 뒤의 3.5 단계에서 만듭니다. 지금은 비워둬도 됩니다.

Work IQ (이번 실습에서는 끄기 권장)

Work IQ는 에이전트를 내 메일, 일정, 문서 같은 M365 맥락에 연결하는 인텔리전스 계층입니다(프리뷰). 개요 화면의 Work IQ 토글로 켜고 끄며, 기본값은 비활성화됨입니다.

켜면 똑똑해지는 면도 있습니다. 내 메일과 일정을 보고 “이 보고 메일을 매주 반복하시네요”처럼 고충을 먼저 짚어줄 수 있죠. 다만 이번 실습은 꺼둡니다. 누구나 같은 결과를 만들어야 하는데, 켜면 사람마다 데이터가 달라 결과가 제각각이고, M365 Copilot 라이선스도 필요하기 때문입니다. “내 업무를 아는 비서형 에이전트”를 만들 때 켜는 기능으로 기억하세요.

ℹ️
켜면 할 수 있는 일 예시. 개인 업무 데이터를 직접 다루는 에이전트라면 유용합니다. “오늘 온 메일 요약”, “빈 시간에 회의 잡기”, “내 문서에서 자료 찾기”처럼 나의 실제 메일과 일정, 문서를 참고해 답하게 만들 수 있습니다. 이런 비서형 에이전트를 만들 때 Outlook, OneDrive, Teams 같은 항목을 켜면 됩니다.

PART 3 3.4 · 인터뷰 토픽

인터뷰 토픽 만들기: 업무 고충 수집

이 토픽의 목적은 사용자의 업무 고충을 한 번에 하나씩 질문해 수집하는 것입니다. 모은 답변은 변수에 담기고, 뒤이어 참조 자료 4종에 근거한 설계 방향(또는 3.5의 설계서)으로 이어집니다.

새 토픽 생성

상단 토픽 탭으로 이동합니다. 필터에서 사용자 지정과 시스템 토픽을 볼 수 있는데, 우리는 새로 만들 것이므로 좌측 상단 + 토픽 추가 → 새로 시작을 누릅니다.

빈 캔버스가 열리고 맨 위에 트리거 노드가 나타납니다.

트리거 설정: ‘토픽이 수행하는 작업 설명’ 입력

생성형 모드에서는 트리거 노드에 이 에이전트 선택이 표시되고, 그 아래 토픽이 수행하는 작업 설명 입력란이 있습니다. 에이전트는 이 설명을 보고 언제 이 토픽을 실행할지 스스로 판단합니다. 입력란(회색 예시 안내가 보이는 칸)을 클릭하고 아래 문장을 그대로 붙여넣으세요.

토픽이 수행하는 작업 설명, 붙여넣어 사용
사용자가 업무의 어려움, 반복 작업, 자동화하고 싶은 일에 대해 이야기할 때 이 토픽을 실행합니다. 사용자의 업무 고충을 한 번에 한 가지씩 질문해 구체화하고, 어떤 업무인지·얼마나 자주 반복되는지·어떤 데이터를 다루는지·결과물 형태는 무엇인지를 파악합니다. 충분히 파악되면 적합한 플랫폼과 에이전트 설계 방향을 제안합니다.

질문 노드 추가

트리거 아래 +를 누르면 노드 추가 메뉴가 열립니다. 질문하기를 선택합니다.

질문 노드가 추가됩니다. 아래 세 칸을 차례로 설정하세요.

  1. 메시지 입력 칸에 사용자에게 보여줄 질문을 적습니다. 첫 질문으로 아래 문구를 붙여넣으세요.
질문어떤 업무가 가장 번거롭거나 반복적인가요? 업무 이름과 함께 간단히 설명해 주세요.
  1. 식별 드롭다운은 기본값이 다중 선택 옵션이라 “옵션이 누락됨” 오류가 납니다. 자유 서술형 답변을 받기 위해 사용자의 전체 응답으로 바꿉니다.
  2. 변수는 사용자의 답변을 담아 두는 상자입니다. 다음 이름으로 사용자 응답 저장 칸에 Var1 상자가 자동으로 생겨 있으니, 그 변수를 클릭해 오른쪽 변수 속성 패널의 변수 이름을 업무고충으로 바꾸면 됩니다.

같은 방식으로 두 번째 질문도 하나 더 만듭니다. 위와 똑같이 + → 질문하기로 노드를 추가하고, 이번엔 식별을 기본값 다중 선택 옵션 그대로 둔 채 보기를 한 줄에 하나씩 입력한 뒤, 변수 이름을 반복주기로 바꿉니다.

💡
다중 선택이라 보기마다 분기(가지)가 자동으로 생기지만, 그 가지들은 다음 노드로 다시 합쳐지니 신경 쓰지 않아도 됩니다. 나머지 항목(다루는 데이터·보안 등급, 결과물 형태)은 3.1 지침에 이미 들어 있어 생성형 오케스트레이션이 알아서 물어봅니다. 순서를 고정하고 싶을 때만 같은 방법으로 노드를 더 추가하세요.

토픽 저장

질문 노드까지 만들었으면 우측 상단 저장을 눌러 토픽을 저장합니다. 토픽은 인터뷰 답변을 모으는 역할까지입니다. 모은 답으로 설계서를 만드는 일은 3.5의 ‘설계서 생성’ 도구가 맡습니다(인터뷰가 끝나면 자동으로 호출됩니다).

💡
3.4는 진짜 선택입니다. 생성형 오케스트레이션(3.3)을 켜 두면 토픽을 아예 안 만들어도 에이전트가 지침만 보고 알아서 인터뷰합니다. 이 토픽은 “질문 순서를 매번 똑같이 고정”하고 싶을 때만 더하는 것입니다. 3.1~3.3 + 참조 자료만으로도 동작하는 에이전트가 됩니다.

💬
“인터뷰 내용”이 뭔가요? 3.1 지침의 인터뷰 항목(어떤 업무, 반복 주기, 처리 시간, 다루는 데이터, 보안 등급, 결과물 형태)에 따라 에이전트가 사용자에게 물어 모은 답변입니다. 생성형 오케스트레이션(3.3)이 켜져 있으면, 에이전트가 대화 내용을 보고 이 인터뷰내용 입력을 자동으로 채워서 이 도구를 호출합니다. 그래서 여기서는 입력을 “정의”만 해 두면 됩니다(값을 직접 넣지 않습니다).

③ 출력을 문서로 바꾸고 레이아웃을 올립니다. 설계서를 표 텍스트가 아니라 깔끔한 Word 문서 파일로 받기 위해, 프롬프트 편집기 오른쪽 위 출력에서 텍스트 대신 문서를 고른 뒤 그 옆 문서 설정을 엽니다. 먼저 아래 레이아웃 파일을 내려받으세요.

문서 레이아웃 업로드의 끌어서 놓거나 찾아보려면 선택에 방금 받은 A4A_Design_Layout.docx를 올립니다. 그러면 레이아웃 안의 채울 필드 목록(예: {{에이전트이름}}, {{추천플랫폼}}, {{지침초안}} 등)이 표시됩니다.

📐
레이아웃을 직접 만들 때 규칙. 채울 자리는 이중 중괄호로 표시합니다(예: {{에이전트이름}}). 표 안의 칸은 표이름.열이름으로 적습니다(예: {{items.수량}}). 필드 이름에 공백을 넣지 않습니다. 레이아웃 파일은 20MB 이하, 암호·기밀 문서가 아니어야 합니다.

④ 모델은 기본값 그대로 두고 테스트를 누릅니다. 테스트하려면 인터뷰내용 입력에 실제 인터뷰 답변 같은 예시 문장을 한 번 넣어야 합니다(설명 문구가 아니라 진짜 내용이어야 문서가 채워집니다). 아래 샘플을 그대로 붙이면, 오른쪽에서 빈칸이 모두 채워진 Word 설계서를 내려받을 수 있습니다.

테스트용 인터뷰내용 샘플, 붙여넣어 사용
매주 월요일에 팀 주간 보고서를 작성합니다. 팀원 5명이 보낸 진행 현황 엑셀과 지난주 회의록을 취합해 요약하고, 표로 정리해 부서장에게 메일로 보냅니다. 한 번에 약 2시간이 걸리고, 가장 번거로운 건 여러 엑셀을 일일이 복사해 합치는 부분입니다. 다루는 자료는 사내 내부 자료(내부 등급)이고, 결과물은 워드 보고서와 요약 메일입니다.
💡
문서 출력은 미리 보기(프리뷰) 기능이라 환경에 따라 문서 옵션이 안 보일 수 있습니다. 그럴 땐 출력을 텍스트로 두고 진행하면, 설계서가 표 형태의 글로 나옵니다(실습에는 지장 없음).
⚙️
맨 아래 완료 → 실행 후는 응답하지 않음(기본값) 그대로 둡니다. “아무것도 안 한다”는 뜻이 아니라, 도구가 만든 설계서를 에이전트에게 돌려주고 에이전트가 사용자에게 답하도록 맡긴다는 뜻입니다. 입력 인터뷰내용도 AI로 채우기로 두면 “AI가 대신 채워주므로 별도 조치가 필요 없습니다”라고 안내됩니다. 마지막으로 저장합니다.

⑤ 도구 이름·설명 지정 (가장 중요)

저장할 때(또는 도구 세부 정보에서) 도구 이름과 설명을 입력합니다. 에이전트는 바로 이 설명을 읽고 “언제 이 도구를 쓸지” 판단하므로, 설명을 명확히 쓰는 게 핵심입니다. 아래를 그대로 넣으세요.

도구 이름설계서 생성
설명사용자의 업무 고충 인터뷰 내용을 받아, 사내 규정과 플랫폼 기준에 맞는 에이전트 제작 설계서를 생성한다. 사용자가 자동화·에이전트 제작·설계서를 요청할 때 호출한다.

저장하면 에이전트의 도구 목록에 설계서 생성이 추가되고, 이때부터 에이전트가 필요할 때 자동으로 이 도구를 부릅니다.

⚙️
추가 세부 정보를 펼치면 두 가지가 더 있습니다. 이 도구를 사용할 수 있는 경우는 “에이전트는 언제든지 이 도구를 사용할 수 있습니다”(기본값) 그대로 두고, 실행하기 전에 최종 사용자에게 질문합니다는 아니요로 둡니다. 그래야 에이전트가 매번 묻지 않고 알아서 도구를 호출합니다.

⑥ 테스트로 도구 호출 확인

새 지침에는 이미 “‘설계서 생성’ 도구를 호출한다”는 규칙이 들어 있어, 따로 한 줄을 더 넣지 않아도 됩니다. 바로 테스트로 확인합니다.

🧪
확인 방법: 우측 상단 테스트에서 “반복되는 보고서 작성이 너무 번거로워요” 같은 말을 넣어 보세요. 에이전트가 인터뷰 질문을 몇 가지 던지고, 답을 모은 뒤 설계서 생성 도구를 호출해 설계서를 만들어내면 성공입니다. 어떤 도구·토픽·지식이 쓰였는지는 테스트 화면의 활동 표시에서 실시간으로 보입니다.
💬
“워드로 받을지 물어봐야 하나요?” 아니요. ‘설계서 생성’ 도구 자체가 Word 문서를 만드는 도구입니다(③에서 출력을 문서로 지정했으니까요). 그래서 지침에 적은 대로 도구를 호출하면 곧 Word 설계서가 나옵니다. 매번 “워드로 받으시겠어요?”라고 되묻지 않아도 됩니다. (꼭 물어보게 하고 싶으면 지침에 설계서를 만들기 전 'Word로 받으시겠어요?'라고 한 번 묻는다. 한 줄을 더하면 됩니다.)

⑦ 에이전트 흐름 만들기 (다음 3.6 승인과 이어짐)

설계서가 완성된 뒤 사람의 검토·승인(3.6)을 붙이려면, 프롬프트 도구만으로는 안 되고 에이전트 흐름(Agent flow)이 필요합니다. 이 흐름은 설계서를 직접 만들지 않고, 에이전트가 만든 설계서 내용을 입력으로 받아 승인을 처리합니다. 여기서 흐름의 뼈대만 만들어 두고, 승인 동작은 3.6에서 이어서 추가합니다.

좌측 흐름 → 새 에이전트 흐름을 만듭니다. 트리거는 When an agent calls the flow(에이전트가 흐름을 호출할 때)이고, 여기에 입력 하나(예: 설계서내용, 텍스트)를 추가합니다. 맨 마지막에는 Respond to the agent(에이전트에 응답)가 있어야 합니다. 그 응답 액션의 Networking에서 Asynchronous response를 Off로 두고, 100초 안에 응답하도록 만든 뒤 게시해야 도구로 쓸 수 있습니다.

ℹ️
이 실습에서는 흐름을 설계서 내용을 입력으로 받아 → 승인을 요청하고 → 결과를 돌려주는 최소 형태로만 만듭니다. 실제 운영에서는 이 흐름에 Word 문서 생성·저장 같은 동작을 더 붙일 수 있습니다.
PART 3 3.6 · 사람의 검토·승인

사람의 검토·승인 단계 추가

🙋
‘사람의 검토·승인(HITL, Human-in-the-loop)’이 뭔가요? 말 그대로 “사람이 중간에 한 번 확인하고 넘어가는” 장치입니다. AI가 만든 설계서를 곧바로 확정하지 않고, 담당자(사람)가 검토·승인한 뒤에만 다음 단계로 진행하도록 만드는 안전장치예요. 중요한 결정이나 대외 공유 전에 사람이 한 번 거르게 하는 용도입니다.

3.5의 마지막 단계(⑦)에서 만든 에이전트 흐름에 이어, 설계서가 완성되면 담당자에게 검토·승인을 요청하는 동작을 붙입니다.

1단계 · 에이전트 흐름 편집기 열기

좌측 메뉴 흐름에서 3.5(⑦)에서 만든 에이전트 흐름을 클릭해 편집기를 엽니다. 트리거(설계서 내용을 입력으로 받음)와 맨 마지막 Respond to the agent(에이전트에 응답) 사이에 승인 동작을 넣을 것입니다.

2단계 · 승인 동작 추가

트리거 아래의 +(새 단계)를 누르고, 검색창에 승인을 입력합니다. 표준 승인 범주가 보이면 그 안의 승인 시작 및 대기(Start and wait for an approval) 동작을 선택합니다.

동작을 추가하면 아래 입력 칸들이 나옵니다. 각 칸을 다음과 같이 채웁니다.

제목A4A 설계서 검토 요청
제안 텍스트AI가 생성한 에이전트 제작 설계서입니다. 내용을 검토하신 뒤 승인 또는 반려해 주세요.
  • 할당 대상: 검토 담당자의 이름이나 이메일 주소를 입력해 사람을 고릅니다(예: 팀 리드 본인 계정으로 테스트). 복사할 값이 아니라 직접 선택하는 칸입니다.
  • 세부 정보: 빈 칸을 클릭하고 /(또는 동적 콘텐츠)로 트리거 입력 설계서내용을 삽입합니다. 이 칸은 Markdown을 지원해 설계서 본문이 그대로 보입니다.
  • 항목 링크 · 항목 링크 설명: 비워 둡니다.
  • 고급 매개 변수의 알림 사용·재할당 사용은 기본값 예 그대로 둡니다.

이렇게 하면 흐름이 여기서 멈추고, 담당자에게 Teams 알림과 이메일로 검토·승인 요청이 갑니다. 담당자가 응답할 때까지 기다립니다.

3단계 · 승인 결과에 따라 분기

승인 동작 아래 + → 조건 추가(Condition)를 넣습니다. 조건은 승인 동작의 결과(Outcome) = Approve로 설정합니다.

  • 예(승인됨) 가지: 다음 단계로 진행 (설계서를 그대로 사용자에게 전달)
  • 아니요(거부됨) 가지: “담당자 검토에서 반려되었습니다. 수정이 필요합니다.” 같은 안내 메시지를 설정

4단계 · 결과를 에이전트로 돌려주기

마지막 Respond to the agent(에이전트에 응답) 동작에서, 승인 결과(승인됨/반려됨)와 최종 설계서를 출력 값에 담습니다. 그런 다음 우측 상단 게시를 눌러 흐름을 저장·게시합니다. (게시해야 에이전트가 이 흐름을 도구로 사용할 수 있습니다.)

🧪
확인: 에이전트 테스트에서 설계서 생성을 요청하면, 담당자에게 승인 요청이 가고 승인하기 전까지는 최종 답이 나오지 않습니다. 담당자가 Teams에서 승인을 누르면 그때 설계서가 사용자에게 전달됩니다.
💬
참고 · 사람 상담사로 연결하고 싶다면(승인과는 다른 기능): 에이전트가 처리하기 어려운 질문을 실제 상담사에게 넘기는 것은 시스템 토픽 에스컬레이션(Escalate)에서 설정합니다. 해당 토픽을 열고 + → 토픽 관리 → 대화 전환 노드를 추가하면 됩니다.
PART 3 3.7 · 테스트·게시

테스트와 게시

에이전트 테스트

우측 상단 테스트를 눌러 오른쪽 에이전트 테스트 패널에서 대화해 봅니다. 에이전트가 인사말로 응답하면 정상입니다. 생성형 모드에서는 어떤 토픽·도구·지식이 선택됐는지 실시간으로 보여주고, 응답을 클릭하면 해당 노드로 이동합니다.

🧪
이렇게 확인해 보세요: 테스트 칸에 “반복되는 주간 보고서 작성이 너무 번거로워요”라고 입력합니다. 에이전트가 업무를 하나씩 되묻고(인터뷰), 마지막에 추천 플랫폼·지침 초안·테스트 시나리오가 담긴 설계서를 만들어 내놓으면 성공입니다.
