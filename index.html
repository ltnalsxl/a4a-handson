누구나 AI 에이전트를 만들도록 돕는
AI 에이전트를 직접 만듭니다

A4A(Agent for Agent)는 이름 그대로 “누구나 에이전트를 만들도록 돕는 에이전트”입니다.

구성원이 업무 고충을 말하면, A4A가 인터뷰 → 사내 지식 그라운딩 → 설계 추천 → 담당자 승인을 거쳐 또 다른 에이전트의 제작 패키지(설계서)를 만들어 줍니다.

이 과정에서 여러분은 에이전트 제작의 전 과정을 자연스럽게 익히게 됩니다.

🎯
오늘의 목표: 단순히 “에이전트 하나”를 만드는 게 아니라, “누구나·안전하게 에이전트를 만들도록 돕는 코치(A4A)”를 직접 구축하면서 에이전트 제작의 핵심을 익힙니다.

PART 1 A4A 소개

A4A란 무엇인가: 누구나 에이전트를 만들도록 돕는 에이전트

A4A를 한 문장으로 정의하면 “누구나 AI 에이전트를 만들도록 돕는 AI 에이전트”입니다. 일반 에이전트와 무엇이 다른지부터 명확히 짚고 갑니다.

일반 에이전트: “일하는” 에이전트

  • → 가격 계산, 문서 요약, 특허 검색처럼 하나의 업무를 직접 수행
  • → 결과물 = 그 업무의 산출물
  • → 비유: 완성된 요리

A4A: “도와주는” 에이전트

  • ★ 업무를 수행하지 않고, 다른 에이전트의 설계서를 생성
  • ★ 결과물 = 에이전트 제작 패키지(.docx)
  • ★ 비유: 요리를 가르쳐주는 요리 선생님
💡
만드는 기술(Agent Builder, Copilot Studio)은 똑같습니다. 다른 건 목적이에요. A4A는 “에이전트 제작” 자체를 도와주는 한 단계 위의 에이전트입니다. 그래서 오늘은 “에이전트 만들기를 도와주는 에이전트”를 직접 만드는 실습을 합니다.
왜 이런 걸 만드나: 목표와 배경

A4A가 풀려는 문제

  • 한두 개의 에이전트를 전문가가 만들어주는 것으로는 조직 전체로 확산되지 않습니다
  • 그렇다고 모두가 자유롭게 만들면 품질 저하·보안 사고(방치되는 에이전트, 미검증 외부 도구 사용, 비용 낭비)가 발생합니다
  • A4A는 “누구나 + 제대로 + 안전하게” 에이전트를 만들도록 돕는 가이드이자 가드레일 역할을 합니다
✓
이 교육의 진짜 목표: A4A를 예제로 만들어보며, 여러분이 앞으로 어떤 에이전트든 직접·안전하게 만들 수 있는 역량을 갖추는 것입니다.

PART 2 Agent Builder 핸즈온

A4A Lite 만들기: 실습 개요

M365 Copilot에 내장된 Agent Builder로 코드 한 줄 없이 5~10분 만에 동작하는 “에이전트 제작 코치(A4A Lite)”를 만듭니다. 별도 라이선스·환경 구축이 필요 없는 노코드 선언형 에이전트입니다.

🧭
왜 같은 A4A를 두 도구로 만드나요?: 오늘은 같은 A4A를 두 가지 도구로 만들어 봅니다. PART 2에서는 Agent Builder로 쉽고 빠르게(노코드), PART 3에서는 Copilot Studio로 정교하게(풀버전). 같은 목표를 두 방식으로 구현해보며 “언제 어떤 도구를 쓰는지”를 익히는 것이 목표입니다.

이 실습을 마치면

  • M365 Copilot에서 새 에이전트로 에이전트를 생성할 수 있습니다
  • 안내·지식·기능·추천 프롬프트를 설정할 수 있습니다
  • 사용해 보기 미리보기로 검증하고 만들기 후 공유할 수 있습니다
🧰
준비물: M365 Copilot 라이선스 계정, 웹 브라우저. 접속: 브라우저에서 microsoft365.com/chat 에 접속하거나 Microsoft 365 Copilot 앱을 엽니다.
PART 2 2.1 · 에이전트 생성 진입

에이전트 생성 진입: 새 에이전트

Microsoft 365 Copilot 앱 열기

브라우저에서 microsoft365.com/chat 에 접속하거나 Microsoft 365 Copilot 앱을 엽니다. 좌측 패널에서 에이전트를 펼친 뒤 새 에이전트를 선택합니다.

생성 방식 이해하기: 자연어 설명 vs 구성

처음 화면에서는 만들려는 에이전트를 자연어로 설명해 자동 생성할 수 있습니다. 이번 실습은 정확한 학습을 위해 구성으로 건너뛰기를 눌러 구성 화면에서 각 항목을 직접 입력합니다.

  • 자연어 설명: 만들려는 에이전트를 문장으로 적으면 이름·설명·안내·지식을 자동 생성(빠른 경로)
  • 구성: 이름·안내·지식·기능을 직접 입력(이번 실습 권장)

구성 화면 살펴보기

상단 탭은 구성(직접 설정)과 사용해 보기(미리보기)로 나뉩니다. 우측 상단 만들기 버튼으로 마지막에 생성합니다.

⚠️
예전 문서의 “Create agent”는 현재 새 에이전트로, “Configure/Try it”은 구성/사용해 보기로 한글화되었습니다.
PART 2 2.2 · 이름·안내 작성

이름·설명·안내 작성

이름과 설명 입력

  • 이름 (제목 옆 연필 아이콘) : A4A 에이전트 제작 코치 (최대 30자)
  • 에이전트 설명하기 (부제) : “구성원의 업무 고충을 듣고 사내 규정에 맞는 에이전트 설계서를 제안하는 코치” (최대 1,000자)

안내 작성

안내 칸은 곧 시스템 프롬프트입니다. 아래 Markdown 구조로 작성합니다 (최대 8,000자).

안내(Instructions) 예시, 붙여넣어 사용
## 목적
당신은 사내 구성원이 업무 고충을 말하면, 자동화할 수 있는
에이전트를 제안하고 제작 설계서를 만들어 주는 코치입니다.

## 대화 진행 방식
1. 아래 항목을 한 번에 하나씩 질문해 업무 고충을 구체화한다.
   - 어떤 업무인가요? (업무 이름과 한 줄 설명)
   - 얼마나 자주 반복되나요? (매일·주간·월간)
   - 한 번 처리에 시간이 얼마나 걸리나요?
   - 어떤 데이터·문서를 다루나요? (보안 등급 포함)
   - 가장 번거롭거나 실수가 잦은 단계는 어디인가요?
   - 결과물은 누구에게, 어떤 형태로 전달되나요?
2. 답변이 모호하면 다음 질문 전에 한 번 더 되물어 명확히 한다.
3. 충분히 파악되면 적합한 플랫폼을 추천하고 이유를 설명한다.
4. 마지막으로 제작 설계서 초안을 표 형태로 제시한다.

## 일반 가이드라인
- 사내 보안 규정(Security_Rule)을 항상 우선 확인하고,
  데이터 등급에 맞는 플랫폼만 추천한다.
- 추측 대신 등록된 지식(Knowledge)에 근거해 답한다.
- 한 번에 한 가지만 질문해 사용자의 부담을 줄인다.
- 정중하고 간결한 존댓말로 답한다.

## 설계서 출력 형식
다음 항목을 표로 정리해 제시한다.
1. 에이전트 이름과 한 줄 목적
2. 추천 플랫폼과 선정 이유
3. 안내(Instructions) 초안
4. 필요한 지식(Knowledge Source) 목록
5. 테스트 시나리오 3개
6. 보안 체크리스트 확인 결과
💡
지침을 구체적으로 적을수록 답이 정확해집니다. 특히 분기 질문을 자세히 적어두면 에이전트가 빠뜨리지 않고 인터뷰합니다.
PART 2 2.3 · 지식 추가

지식 추가

지식 원본 선택

구성 탭의 지식 영역은 “에이전트가 응답을 생성하는 데 사용할 원본”을 등록하는 곳입니다. 파일, 모임, 채팅, 이메일 및 웹 사이트 추가에서 원본을 고릅니다.

실습 문서 업로드

  • 파일 업로드: 내려받은 Security_Rule.docx 등 4종 파일을 입력창에 끌어다 놓거나 업로드 아이콘으로 추가
  • URL 또는 이름 입력: SharePoint/OneDrive 링크 (2단계 이하 경로, 쿼리 파라미터 없이)
  • 모든 웹 사이트를 검색합니다: 공개 웹 검색 토글 / 지정된 원본만 사용: 등록 자료만 근거로 답하게 제한

업로드하면 업로드된 파일 목록에 표시되고, 잠시 준비 중 상태를 거쳐 사용 가능해집니다.

지식 원본등록 한도(에이전트당)
업로드 파일최대 20개
SharePoint 파일최대 100개
OneDrive 파일최대 50개
공개 웹사이트 URL최대 4개 (2단계 이하)
전체 지식 원본(합계)최대 20개
⚠️

PART 3 Copilot Studio 핸즈온

풀버전 A4A 구현: 실습 개요

Microsoft Copilot Studio로 Knowledge 그라운딩, Tools, Topics, 생성형 오케스트레이션, 그리고 사람의 검토·승인(HITL, 사람이 중간에 확인하는 단계)까지 갖춘 본격 에이전트를 만듭니다.

🧭
PART 2에서 노코드로 가볍게 만든 A4A를, 이번엔 실제 업무에 쓸 수 있는 수준으로 끌어올립니다. 같은 A4A지만, 인터뷰 흐름(Topic), 사내 지식 연결(Knowledge), 설계서 생성 도구(Tools), 담당자 검토·승인까지 갖춰 “제대로 동작하는 제작 코치”를 완성합니다.
✅
어디까지 하면 동작하나요? 3.1 생성 → 3.2 참조 자료 등록 → 3.7 게시만 해도 목표(인터뷰 → 설계서 제안)가 동작하는 에이전트가 나옵니다. 3.4 인터뷰 토픽, 3.5 설계서 도구, 3.6 검토·승인은 품질을 끌어올리는 선택(심화) 단계입니다. 시간이 부족하면 3.1·3.2·3.3·3.7만 진행해도 됩니다.

🔗 구성 한눈에: 우리 A4A는 어떻게 인터뷰하고 설계서를 만드나?

핵심: 생성형 오케스트레이션이 켜져 있으면(3.3), 에이전트가 지침 + 참조 자료 + (있다면) 토픽·도구를 상황에 맞게 스스로 골라서 동작합니다. 우리가 “이 순서로 이걸 불러라”라고 일일이 연결하지 않습니다.

  • 지침(Instructions) = 에이전트의 성격·대화 방식·출력 형식을 정하는 시스템 프롬프트. “한 번에 하나씩 인터뷰하고, 마지막에 설계서를 표로 출력하라”가 여기 들어 있습니다.
  • 참조 자료(4종) = 답변의 근거. 에이전트가 필요할 때 알아서 검색합니다.
  • 도구·토픽 = 에이전트가 이름·설명을 보고 필요하다고 판단하면 자동으로 호출합니다. 입력값이 필요하면 사용자에게 직접 질문을 만들어 물어본 뒤 채웁니다.
❓
“지침에 도구를 부르는 코드가 하나도 없는데 맞나요?” 네, 맞습니다. 생성형 모드에서는 지침에서 도구를 직접 호출하지 않습니다. 에이전트가 도구의 이름·설명을 보고 알아서 부릅니다. 그래서 도구 이름·설명을 명확히 쓰는 것이 가장 중요합니다(원하면 지침에 “설계서를 만들 땐 ○○ 도구를 쓴다” 한 줄을 더해 확실히 할 수 있습니다(3.5 참고).

그래서 가장 단순한 정답은: 지침을 잘 쓰고(3.1) + 참조 자료 4종을 올리면(3.2), 토픽·도구 없이도 에이전트가 인터뷰하고 사내 규정에 맞는 설계서를 표로 내놓습니다. 3.4·3.5는 “인터뷰 순서를 고정”하거나 “설계서 형식을 매번 똑같이” 하고 싶을 때 더하는 심화입니다.

이 실습을 마치면

  • Copilot Studio에서 에이전트를 생성하고 Knowledge 4종을 등록할 수 있습니다
  • 인터뷰용 Topic과 설계서 생성용 Tool(프롬프트/플로우)을 만들 수 있습니다
  • 생성형 오케스트레이션을 이해하고 테스트 후 게시할 수 있습니다
📝
용어 안내: 이 도구는 예전 “Power Virtual Agents”에서 Copilot Studio로 이름이 바뀌었고, 예전의 Actions/Plugins는 모두 도구(Tools)로 통합되었습니다. 챗봇은 에이전트(Agent)로 부릅니다.
PART 3 3.1 · 에이전트 생성

에이전트 생성

Copilot Studio 접속

브라우저에서 copilotstudio.microsoft.com 에 접속합니다. 홈 화면에 “무엇을 빌드하시겠습니까?”와 에이전트/워크플로 토글, 자연어 입력 상자가 보입니다. 우측 상단 환경은 교육용 환경이 따로 안내되었다면 그 환경을 선택하고, 그렇지 않으면 안내에 따라 주세요.

빈 에이전트로 시작

정확한 학습을 위해 자연어 생성 대신 직접 만듭니다. 좌측 에이전트 아이콘을 눌러 에이전트 페이지로 간 뒤, 우측 상단 + 빈 에이전트 만들기를 누릅니다.

에이전트 이름 지정 팝업이 열리면 에이전트 이름을 입력합니다. 언어·솔루션 등을 직접 지정하려면 에이전트 설정(선택 사항)을 펼쳐 설정한 뒤, 만들기를 누릅니다.

▸ 에이전트 설정(선택 사항) 자세히: 언어·솔루션·전용 솔루션 만들기

에이전트 설정(선택 사항)을 펼치면 아래 항목을 직접 고를 수 있습니다.

  • 언어: 한국어(대한민국) 선택
  • 솔루션: 에이전트가 담길 솔루션. 회사에서 안내한 지정 솔루션이 있으면 그것을 고르고, 없으면 기본 솔루션(Common Data Services Default Solution) 그대로 둬도 됩니다.
  • 스키마 이름: 자동으로 채워집니다(예: cr940_). 그대로 두면 됩니다.

전용 솔루션을 새로 만들고 싶다면 (교육·공유 환경 정리용, 선택):

  1. 좌측 사이드바 맨 아래 …(더 보기) → 살펴보기 → 솔루션을 엽니다.
  2. 상단 + 새 솔루션을 누릅니다.
  3. 오른쪽 패널에서 표시 이름·이름·게시자·버전(기본 1.0.0.0)을 입력하고 만들기. (이 솔루션을 기본으로 쓰려면 선호하는 솔루션으로 설정 체크)
  4. 다시 에이전트를 만들 때 에이전트 설정(선택 사항)의 솔루션 드롭다운에서 방금 만든 솔루션을 고릅니다.
💡
솔루션을 안 만들어도 에이전트는 자동으로 기본 솔루션에 담겨 정상 동작합니다. 전용 솔루션은 정리·이관·배포가 편해지는 선택 사항일 뿐입니다.

기본 정보 입력

생성 직후 개요 페이지가 열립니다. 세부 정보 섹션의 편집으로 이름·설명을, 아래쪽 지침 섹션의 편집으로 지침을 입력합니다. 각 편집 창에 입력한 뒤에는 저장(또는 완료)을 눌러야 반영됩니다. 아래 내용을 그대로 복사해 붙여넣으세요.

이름A4A 제작 코치
설명구성원의 업무 고충을 듣고 사내 규정에 맞는 에이전트 설계서를 제안하는 코치

지침에는 아래 지침을 붙여넣습니다 (PART 2와 동일, 최대 8,000자).

지침, 붙여넣어 사용
## 목적
당신은 사내 구성원이 업무 고충을 말하면, 자동화할 수 있는
에이전트를 제안하고 제작 설계서를 만들어 주는 코치입니다.

## 대화 진행 방식
1. 아래 항목을 한 번에 하나씩 질문해 업무 고충을 구체화한다.
   - 어떤 업무인가요? (업무 이름과 한 줄 설명)
   - 얼마나 자주 반복되나요? (매일·주간·월간)
   - 한 번 처리에 시간이 얼마나 걸리나요?
   - 어떤 데이터·문서를 다루나요? (보안 등급 포함)
   - 가장 번거롭거나 실수가 잦은 단계는 어디인가요?
   - 결과물은 누구에게, 어떤 형태로 전달되나요?
2. 답변이 모호하면 다음 질문 전에 한 번 더 되물어 명확히 한다.
3. 충분히 파악되면 적합한 플랫폼을 추천하고 이유를 설명한다.
4. 마지막으로 제작 설계서 초안을 표 형태로 제시한다.

## 일반 가이드라인
- 사내 보안 규정(Security_Rule)을 항상 우선 확인하고,
  데이터 등급에 맞는 플랫폼만 추천한다.
- 추측 대신 등록된 지식(Knowledge)에 근거해 답한다.
- 한 번에 한 가지만 질문해 사용자의 부담을 줄인다.
- 정중하고 간결한 존댓말로 답한다.

1. 에이전트 이름과 한 줄 목적
2. 추천 플랫폼과 선정 이유
3. 안내(Instructions) 초안
4. 필요한 지식(Knowledge Source) 목록
5. 테스트 시나리오 3개
6. 보안 체크리스트 확인 결과
🧭
에이전트 화면 구성: 생성 후 개요 페이지가 열리고, 상단 탭으로 참조 자료 · 도구 · 에이전트 · 토픽 · 활동 · 평가 · 분석 · 채널로 이동합니다. 우측 상단에는 게시 · 설정 · 테스트 버튼이 있습니다.
🤖
모델 확인: 개요 페이지의 에이전트의 모델 선택에서 에이전트가 추론·응답에 쓰는 모델을 고를 수 있습니다(예: Claude Sonnet 4.6). 실습은 기본값 그대로 두면 됩니다.
💡
솔루션은 환경에 맞춰 고르세요. 에이전트는 어떤 솔루션이든 하나에 담깁니다. 아무것도 안 고르면 자동으로 기본 솔루션(Common Data Services Default Solution)에 들어갑니다. 다만 교육·공유 환경에서는 전용 솔루션을 쓰는 편이 정리에 좋습니다. 회사에서 안내한 지정 솔루션이 있으면 에이전트 설정(선택 사항)을 펼쳐 그 솔루션을 선택하고, 따로 없으면 기본 솔루션 그대로 진행해도 됩니다. (전용 솔루션을 새로 만드는 방법은 위 ‘에이전트 설정(선택 사항) 자세히’를 펼쳐 보세요.)
PART 3 3.2 · 참조 자료 추가

  • Platform_Rule.docx

PART 3 3.2b · 웹 검색·도구·Work IQ

Overview의 추가 설정: 웹 검색·도구·Work IQ

같은 개요 화면에는 참조 자료 외에도 몇 가지 설정이 더 있습니다. A4A에 맞게 어떻게 둘지 정리합니다.

웹 검색 (Web search)

에이전트가 공개 웹사이트를 검색할 수 있게 하는 토글입니다. A4A는 사내 규정·자료에 근거해 답해야 하므로, 정확도를 위해 꺼두는 것을 권장합니다. 일반 상식이나 외부 정보까지 폭넓게 답하게 하려면 켜도 됩니다.

도구 (Tools)

도구 추가로 에이전트가 실제 작업(설계서 생성, 메일 발송 등)을 하도록 기능을 붙입니다. A4A의 설계서 생성 도구는 뒤의 3.5 단계에서 만듭니다. 지금은 비워둬도 됩니다.

Work IQ (선택, 프리뷰)

에이전트를 내 메일·일정·SharePoint·OneDrive·Teams·Word 등 M365 맥락에 연결해, 개인·조직 상황을 이해하도록 돕는 인텔리전스 계층입니다. 켜면 Copilot·Outlook·SharePoint·OneDrive·Teams·Word 같은 항목을 개별로 활성화할 수 있습니다.

  • A4A 실습에서는 꺼두거나 기본값 그대로 둬도 됩니다. 업로드한 4종 지식만으로 충분히 동작합니다.
  • 실제로 “내 메일 요약”, “내 일정 기반 일정 잡기”처럼 개인 업무 데이터를 다루는 에이전트를 만들 때 해당 항목을 켜면 됩니다.
  • M365 Copilot 라이선스가 필요하고, 항목에 따라 연결(로그인) 동의가 한 번 필요합니다.
ℹ️
Work IQ는 미리 보기(프리뷰) 기능이라 화면 구성이 환경에 따라 다를 수 있습니다. 켜는 항목은 “이 에이전트가 어떤 개인·조직 데이터를 참고하면 좋은가”를 기준으로 고르면 됩니다.
PART 3 3.3 · 생성형 오케스트레이션

생성형 오케스트레이션 확인

설정 → 생성형 AI

우측 상단 설정 → 생성형 AI에서 오케스트레이션이 생성형(Generative)으로 되어 있는지 확인합니다(신규 에이전트 기본값).

  • 생성형(기본): 토픽·도구·지식을 에이전트가 자동 선택, 트리거 문구를 따로 안 적어도 됨
  • 클래식: 토픽마다 트리거 문구 5~10개로 매칭

근거 없는 응답 허용 검토

같은 화면에서 “지식에 근거하지 않은 응답 허용” 옵션을 끄면, 등록한 지식·도구에 근거하지 않은 답변을 줄여 환각을 막을 수 있습니다.

🚦
여기까지가 “동작하는 A4A”의 최소 구성입니다. 3.1(생성·지침) + 3.2(참조 자료 4종) + 3.3(생성형 확인)까지 했다면, 바로 3.7 테스트·게시로 건너뛰어도 인터뷰하고 설계서를 내놓는 에이전트가 완성됩니다. 이어지는 3.4 인터뷰 토픽 · 3.5 설계서 도구 · 3.6 승인은 품질을 끌어올리는 선택(심화) 단계입니다.
PART 3 3.4 · 인터뷰 토픽

인터뷰 토픽 만들기: 업무 고충 수집

새 토픽 생성

상단 토픽 탭으로 이동합니다. 필터에서 사용자 지정과 시스템 토픽을 볼 수 있는데, 우리는 새로 만들 것이므로 좌측 상단 + 토픽 추가 → 새로 시작을 누릅니다.

빈 캔버스가 열리고 맨 위에 트리거 노드가 나타납니다.

트리거 설정: ‘토픽이 수행하는 작업 설명’ 입력

생성형 모드에서는 트리거 노드에 이 에이전트 선택이 표시되고, 그 아래 토픽이 수행하는 작업 설명 입력란이 있습니다. 에이전트는 이 설명을 보고 언제 이 토픽을 실행할지 스스로 판단합니다. 입력란(회색 예시 안내가 보이는 칸)을 클릭하고 아래 문장을 그대로 붙여넣으세요.

토픽이 수행하는 작업 설명, 붙여넣어 사용
사용자가 업무의 어려움, 반복 작업, 자동화하고 싶은 일에 대해 이야기할 때 이 토픽을 실행합니다. 사용자의 업무 고충을 한 번에 한 가지씩 질문해 구체화하고, 어떤 업무인지·얼마나 자주 반복되는지·어떤 데이터를 다루는지·결과물 형태는 무엇인지를 파악합니다. 충분히 파악되면 적합한 플랫폼과 에이전트 설계 방향을 제안합니다.

질문 노드 추가

트리거 아래 +를 누르면 노드 추가 메뉴가 열립니다. 질문하기를 선택합니다.

질문 노드가 추가됩니다. 아래 세 칸을 차례로 설정하세요.

  1. 메시지 입력 칸에 사용자에게 보여줄 질문을 적습니다. 첫 질문으로 아래 문구를 붙여넣으세요.
질문어떤 업무가 가장 번거롭거나 반복적인가요? 업무 이름과 함께 간단히 설명해 주세요.
  1. 식별 드롭다운은 기본값이 다중 선택 옵션이라 “옵션이 누락됨” 오류가 납니다. 자유 서술형 답변을 받기 위해 사용자의 전체 응답으로 바꿉니다.
  2. 다음 이름으로 사용자 응답 저장에 변수가 Var1로 자동 생성됩니다. 이름을 클릭해 업무고충으로 바꿉니다. (이 변수에 사용자의 답변이 저장됩니다.)
🔁
질문을 더 받고 싶으면 같은 방식으로 질문 노드를 하나씩 더 추가하면 됩니다(예: 반복 주기, 다루는 데이터, 결과물 형태). 이때 변수명도 반복주기·참조데이터·결과물형태처럼 서로 다르게 지정하세요. 한 번에 한 질문씩 묻는 구조라, 노드 하나에 여러 질문을 넣지 않습니다.

지식 기반 답변 노드 추가

질문 노드 아래 + → 고급 → 생성형 답변 만들기를 추가합니다. 입력에는 앞에서 저장한 변수 업무고충을 넣고, 데이터 원본의 편집에서 등록한 참조 자료 4종을 검색하도록 둡니다. 그러면 사내 규정에 맞는 설계 방향을 답합니다.

마지막으로 우측 상단 저장을 눌러 토픽을 저장합니다.

💡
생성형 오케스트레이션(3.3)을 켜 두면, 사실 인터뷰 토픽을 직접 안 만들어도 에이전트가 지침과 지식만으로 질문하고 답합니다. 이 토픽은 “정해진 순서로 꼭 물어볼 항목”을 보장하고 싶을 때 추가하는 것입니다. 토픽 없이 3.1~3.3 + 지식만으로도 동작하는 에이전트가 됩니다.
PART 3 3.5 · 설계서 생성 도구

설계서 생성 도구 추가 (심화)

이 단계는 “설계서를 매번 똑같은 형식으로” 만들고 싶을 때 더하는 심화입니다. 앞서 본 대로, 에이전트는 이 도구를 이름·설명을 보고 스스로 호출하고, 필요한 입력은 사용자에게 직접 질문해 채웁니다.

도구 추가 열기

상단 도구 탭(또는 개요의 도구 섹션)에서 + 도구 추가 → 새 도구를 누르고 도구 유형을 고릅니다.

도구 유형용도
프롬프트(Prompt)단일 LLM 프롬프트, 인터뷰 결과를 설계서 형식으로 구조화(지식 참조 가능)
에이전트 흐름(Agent flow)로우코드 자동화, Word 생성·SharePoint 업로드·승인

Model Context ProtocolMCP 서버 연결(신규)
REST API · 컴퓨터 사용REST 엔드포인트 연결, 화면 조작 자동화(고급)

프롬프트 도구로 설계서 구조화

새 도구 → 프롬프트를 선택하면 프롬프트 편집기가 열립니다. 화면이 두 칸으로 나뉘는데, 왼쪽 지침 칸이 곧 프롬프트 본문이고 오른쪽 모델 응답은 테스트 결과가 보이는 곳입니다.

❓
어디에 붙여넣나요? 가운데 큰 지침 칸(“Copilot을 사용하여 지침을 만들거나 여기에 작성하세요…”)에 붙여넣습니다. 아래쪽 작은 프롬프트 도우미 칸은 “자연어로 설명하면 프롬프트를 자동 생성”해 주는 보조 도구라, 직접 붙여넣을 때는 쓰지 않습니다.

① 먼저 아래 본문을 지침 칸에 붙여넣습니다.

지침 칸에 붙여넣어 사용
아래 업무 인터뷰 내용을 바탕으로 에이전트 제작 설계서를 만들어 주세요.
사내 규정(Security_Rule)과 플랫폼 기준(Platform_Rule)에 어긋나지 않게 작성합니다.

[업무 인터뷰 내용]
（여기에 입력 변수 인터뷰내용 삽입）

[출력 형식: 아래 항목을 표로]
1. 에이전트 이름과 한 줄 목적
2. 추천 플랫폼(Agent Builder 또는 Copilot Studio)과 선정 이유
3. 지침(Instructions) 초안
4. 필요한 참조 자료(Knowledge Source) 목록
5. 테스트 시나리오 3개
6. 보안 체크리스트 확인 결과

② （여기에 입력 변수 인터뷰내용 삽입） 줄을 지우고, 그 자리에서 / 를 입력합니다. 뜨는 메뉴에서 입력 추가(또는 + 콘텐츠 추가 → 입력)를 고르고, 입력 이름을 아래처럼 만듭니다. 그러면 지침 안에 파란색 입력 칩이 생깁니다.

입력 이름인터뷰내용
설명사용자와의 인터뷰에서 모은 업무 고충 요약(어떤 업무·반복 주기·다루는 데이터·결과물 형태)
💬
“인터뷰 내용”이 뭔가요? 3.4에서 만든 인터뷰 토픽이 사용자에게 질문해 업무고충 변수 등에 모은 답변입니다. 생성형 오케스트레이션(3.3)이 켜져 있으면, 에이전트가 대화 내용을 보고 이 인터뷰내용 입력을 자동으로 채워서 이 도구를 호출합니다. 그래서 여기서는 입력을 “정의”만 해 두면 됩니다(값을 직접 넣지 않습니다).

③ 우측 상단 모델은 기본값(예: GPT-4.1 mini) 그대로 두고, 테스트를 눌러 오른쪽 모델 응답에서 표가 잘 나오는지 확인합니다. (테스트 시 인터뷰내용에 예시 문장을 한 번 넣어 보면 됩니다.) 마지막으로 저장을 누릅니다.

💡
참조 자료도 넣고 싶다면? + 콘텐츠 추가 → 참조 자료(지식)로 업로드한 4종을 이 프롬프트에 직접 붙일 수 있습니다. 다만 에이전트에 이미 4종이 참조 자료로 등록돼 있어, 실습에서는 입력 변수만 만들어도 충분합니다.

④ 도구 이름·설명 지정 (가장 중요)

저장할 때(또는 도구 세부 정보에서) 도구 이름과 설명을 입력합니다. 에이전트는 바로 이 설명을 읽고 “언제 이 도구를 쓸지” 판단하므로, 설명을 명확히 쓰는 게 핵심입니다. 아래를 그대로 넣으세요.

도구 이름설계서 생성
설명사용자의 업무 고충 인터뷰 내용을 받아, 사내 규정과 플랫폼 기준에 맞는 에이전트 제작 설계서를 표 형식으로 생성한다. 사용자가 자동화·에이전트 제작·설계서를 요청할 때 호출한다.

저장하면 에이전트의 도구 목록에 설계서 생성이 추가되고, 이때부터 에이전트가 필요할 때 자동으로 이 도구를 부릅니다.

⑤ (선택) 지침에 도구 사용 규칙 한 줄 추가

도구 설명만으로도 대개 잘 호출되지만, 더 확실하게 하려면 3.1에서 입력한 지침의 “설계서 출력 형식” 부분에 아래 한 줄을 더해 두면 좋습니다.

지침에 추가(선택), 붙여넣어 사용
설계서를 작성할 때는 반드시 '설계서 생성' 도구를 호출해 표 형식으로 출력한다.
🧪
확인 방법: 우측 상단 테스트에서 “반복되는 보고서 작성이 너무 번거로워요” 같은 말을 넣어 보세요. 에이전트가 인터뷰 질문을 던지고, 답을 모은 뒤 설계서 생성 도구를 호출해 표를 내놓으면 성공입니다. 어떤 도구·토픽·지식이 쓰였는지는 테스트 화면의 활동 표시에서 실시간으로 보입니다.

(선택) 에이전트 흐름으로 Word·승인 연결

좌측 흐름 → 새 에이전트 흐름. 트리거는 When an agent calls the flow, 마지막에 Respond to the agent가 있어야 합니다. 그 액션의 Networking에서 Asynchronous response를 Off로 두고, 100초 내 응답한 뒤 게시해야 도구로 쓸 수 있습니다.

  • Word 템플릿 채우기 → SharePoint 업로드
  • Human in the loop 액션으로 승인 요청(다음 단계)
PART 3 3.6 · 사람의 검토·승인

사람의 검토·승인 단계 추가 (심화)

🙋
‘사람의 검토·승인(HITL, Human-in-the-loop)’이 뭔가요? 말 그대로 “사람이 중간에 한 번 확인하고 넘어가는” 장치입니다. AI가 만든 설계서를 곧바로 확정하지 않고, 담당자(사람)가 검토·승인한 뒤에만 다음 단계로 진행하도록 만드는 안전장치예요. 중요한 결정이나 대외 공유 전에 사람이 한 번 거르게 하는 용도입니다.

이 단계는 3.5에서 ‘에이전트 흐름(Agent flow)’으로 설계서 도구를 만든 경우에만 이어서 진행합니다. 프롬프트 도구만 만들었다면 승인 단계가 없으니 건너뛰어도 됩니다.

1단계 · 에이전트 흐름 편집기 열기

좌측 메뉴 흐름에서 3.5에서 만든 에이전트 흐름을 클릭해 편집기를 엽니다. 설계서를 만드는 마지막 동작과 Respond to the agent(에이전트에 응답) 사이에 승인 단계를 넣을 것입니다.

2단계 · 승인 동작 추가

설계서를 만드는 동작 아래의 +(새 단계)를 누르고, 검색창에 승인을 입력합니다. Approvals(승인) 커넥터의 Start and wait for an approval(승인 시작 및 대기) 동작을 선택합니다.

  • 승인 유형: 승인/거부 - 첫 번째 응답(Approve/Reject – First to respond)
  • 제목: A4A 설계서 검토 요청
  • 할당 대상: 검토 담당자의 이메일 주소(예: 팀 리드)
  • 세부 정보: 앞 단계에서 만든 설계서 내용(동적 콘텐츠로 삽입)

이렇게 하면 흐름이 여기서 멈추고, 담당자에게 Teams 알림과 이메일로 승인 요청이 갑니다. 담당자가 응답할 때까지 기다립니다.

3단계 · 승인 결과에 따라 분기

승인 동작 아래 + → 조건 추가(Condition)를 넣습니다. 조건은 승인 동작의 결과(Outcome) = Approve로 설정합니다.

  • 예(승인됨) 가지: 다음 단계로 진행 (설계서를 그대로 사용자에게 전달)
  • 아니요(거부됨) 가지: “담당자 검토에서 반려되었습니다. 수정이 필요합니다.” 같은 안내 메시지를 설정

4단계 · 결과를 에이전트로 돌려주기

마지막 Respond to the agent(에이전트에 응답) 동작에서, 승인 결과(승인됨/반려됨)와 최종 설계서를 출력 값에 담습니다. 그런 다음 우측 상단 게시를 눌러 흐름을 저장·게시합니다. (게시해야 에이전트가 이 흐름을 도구로 사용할 수 있습니다.)

🧪
확인: 에이전트 테스트에서 설계서 생성을 요청하면, 담당자에게 승인 요청이 가고 승인하기 전까지는 최종 답이 나오지 않습니다. 담당자가 Teams에서 승인을 누르면 그때 설계서가 사용자에게 전달됩니다.
💬
참고 · 사람 상담사로 연결하고 싶다면(승인과는 다른 기능): 에이전트가 처리하기 어려운 질문을 실제 상담사에게 넘기는 것은 시스템 토픽 에스컬레이션(Escalate)에서 설정합니다. 해당 토픽을 열고 + → 토픽 관리 → 대화 전환 노드를 추가하면 됩니다.
PART 3 3.7 · 테스트·게시

테스트와 게시

에이전트 테스트

우측 상단 테스트를 눌러 오른쪽 에이전트 테스트 패널에서 대화해 봅니다. 에이전트가 인사말로 응답하면 정상입니다. 생성형 모드에서는 어떤 토픽·도구·지식이 선택됐는지 실시간으로 보여주고, 응답을 클릭하면 해당 노드로 이동합니다.

🧪
이렇게 확인해 보세요: 테스트 칸에 “반복되는 주간 보고서 작성이 너무 번거로워요”라고 입력합니다. 에이전트가 업무를 하나씩 되묻고(인터뷰), 마지막에 추천 플랫폼·지침 초안·테스트 시나리오가 담긴 설계서를 표로 내놓으면 성공입니다.

게시

우측 상단 게시 → 확인 → 게시 완료(수 분 소요).

채널 연결

채널에서 Teams 및 Microsoft 365 Copilot을 추가하면 사내에서 바로 사용할 수 있습니다. 조직 배포는 관리자 승인 요청으로 관리자 승인을 받습니다.

🎉
축하합니다! 인터뷰부터 설계서 생성·승인·게시까지 이어지는 풀버전 A4A를 완성했습니다.
