AI 에이전트를 만들어주는
AI 에이전트를 직접 만듭니다

A4A(Agent for Agent)는 이름 그대로 “에이전트를 만들어주는 에이전트”입니다.

구성원이 업무 고충을 말하면, A4A가 인터뷰 → 사내 지식 그라운딩 → 설계 추천 → 담당자 승인을 거쳐 또 다른 에이전트의 제작 패키지(설계서)를 만들어 줍니다.

이 과정에서 여러분은 에이전트 제작의 전 과정을 자연스럽게 익히게 됩니다.

🎯
오늘의 목표: 단순히 “에이전트 하나”를 만드는 게 아니라, “누구나·안전하게 에이전트를 만들도록 돕는 코치(A4A)”를 직접 구축하면서 에이전트 제작의 핵심을 체득합니다.

PART 1 A4A 소개

A4A란 무엇인가: 에이전트를 만드는 에이전트

A4A를 한 문장으로 정의하면 “AI 에이전트를 만들어주는 AI 에이전트”입니다. 일반 에이전트와 무엇이 다른지부터 명확히 짚고 갑니다.

일반 에이전트: “일하는” 에이전트

  • → 가격 계산, 문서 요약, 특허 검색처럼 하나의 업무를 직접 수행
  • → 결과물 = 그 업무의 산출물
  • → 비유: 완성된 요리

A4A: “만들어주는” 에이전트

  • ★ 업무를 수행하지 않고, 다른 에이전트의 설계서를 생성
  • ★ 결과물 = 에이전트 제작 패키지(.docx)
  • ★ 비유: 요리를 가르쳐주는 요리 선생님
💡
핵심: 만드는 기술(Agent Builder·Copilot Studio)은 똑같습니다. 다른 것은 목적의 층위입니다. A4A는 “에이전트 제작” 자체를 도와주는 한 단계 위의 에이전트예요. 그래서 오늘 우리는 “에이전트를 만드는 에이전트”를 만드는 실습을 합니다.
왜 이런 걸 만드나: 목표와 배경

A4A가 풀려는 문제

  • 한두 개의 에이전트를 전문가가 만들어주는 것으로는 조직 전체로 확산되지 않습니다
  • 그렇다고 모두가 자유롭게 만들면 품질 저하·보안 사고(방치되는 에이전트, 미검증 외부 도구 사용, 비용 낭비)가 발생합니다
  • A4A는 “누구나 + 제대로 + 안전하게” 에이전트를 만들도록 돕는 가이드이자 가드레일 역할을 합니다
✓
이 교육의 진짜 목표: A4A를 예제로 만들어보며, 여러분이 앞으로 어떤 에이전트든 직접·안전하게 만들 수 있는 역량을 갖추는 것입니다.

PART 2 Agent Builder 핸즈온

A4A Lite 만들기: 실습 개요

M365 Copilot에 내장된 Agent Builder로 코드 한 줄 없이 5~10분 만에 동작하는 “에이전트 제작 코치(A4A Lite)”를 만듭니다. 별도 라이선스·환경 구축이 필요 없는 노코드 선언형 에이전트입니다.

🧭
왜 같은 A4A를 두 도구로 만드나요?: 오늘은 같은 A4A를 두 가지 도구로 만들어 봅니다. PART 2에서는 Agent Builder로 쉽고 빠르게(노코드), PART 3에서는 Copilot Studio로 정교하게(풀버전). 같은 목표를 두 방식으로 구현해보며 “언제 어떤 도구를 쓰는지”를 체득하는 것이 핵심입니다.

이 실습을 마치면

  • M365 Copilot에서 새 에이전트로 에이전트를 생성할 수 있습니다
  • 안내·지식·기능·추천 프롬프트를 설정할 수 있습니다
  • 사용해 보기 미리보기로 검증하고 만들기 후 공유할 수 있습니다
🧰
준비물: M365 Copilot 라이선스 계정, 웹 브라우저. 접속: 브라우저에서 microsoft365.com/chat 에 접속하거나 Microsoft 365 Copilot 앱을 엽니다.
PART 2 2.1 · 에이전트 생성 진입

에이전트 생성 진입: 새 에이전트

Microsoft 365 Copilot 앱 열기

브라우저에서 microsoft365.com/chat 에 접속하거나 Microsoft 365 Copilot 앱을 엽니다. 좌측 패널에서 에이전트를 펼친 뒤 새 에이전트를 선택합니다.

생성 방식 이해하기: 자연어 설명 vs 구성

처음 화면에서는 만들려는 에이전트를 자연어로 설명해 자동 생성할 수 있습니다. 이번 실습은 정확한 학습을 위해 구성으로 건너뛰기를 눌러 구성 화면에서 각 항목을 직접 입력합니다.

  • 자연어 설명: 만들려는 에이전트를 문장으로 적으면 이름·설명·안내·지식을 자동 생성(빠른 경로)
  • 구성: 이름·안내·지식·기능을 직접 입력(이번 실습 권장)

구성 화면 살펴보기

상단 탭은 구성(직접 설정)과 사용해 보기(미리보기)로 나뉩니다. 우측 상단 만들기 버튼으로 마지막에 생성합니다.

⚠️
예전 문서의 “Create agent”는 현재 새 에이전트로, “Configure/Try it”은 구성/사용해 보기로 한글화되었습니다.
PART 2 2.2 · 이름·안내 작성

이름·설명·안내 작성

이름과 설명 입력

  • 이름 (제목 옆 연필 아이콘) : A4A 에이전트 제작 코치 (최대 30자)
  • 에이전트 설명하기 (부제) : “구성원의 업무 고충을 듣고 사내 규정에 맞는 에이전트 설계서를 제안하는 코치” (최대 1,000자)

안내 작성

안내 칸은 곧 시스템 프롬프트입니다. 아래 Markdown 구조로 작성합니다 (최대 8,000자).

안내(Instructions) 예시, 붙여넣어 사용
## 목적
당신은 사내 구성원이 업무 고충을 말하면, 자동화할 수 있는
에이전트를 제안하고 제작 설계서를 만들어 주는 코치입니다.

## 대화 진행 방식
1. 아래 항목을 한 번에 하나씩 질문해 업무 고충을 구체화한다.
   - 어떤 업무인가요? (업무 이름과 한 줄 설명)
   - 얼마나 자주 반복되나요? (매일·주간·월간)
   - 한 번 처리에 시간이 얼마나 걸리나요?
   - 어떤 데이터·문서를 다루나요? (보안 등급 포함)
   - 가장 번거롭거나 실수가 잦은 단계는 어디인가요?
   - 결과물은 누구에게, 어떤 형태로 전달되나요?
2. 답변이 모호하면 다음 질문 전에 한 번 더 되물어 명확히 한다.
3. 충분히 파악되면 적합한 플랫폼을 추천하고 이유를 설명한다.
4. 마지막으로 제작 설계서 초안을 표 형태로 제시한다.

## 일반 가이드라인
- 사내 보안 규정(Security_Rule)을 항상 우선 확인하고,
  데이터 등급에 맞는 플랫폼만 추천한다.
- 추측 대신 등록된 지식(Knowledge)에 근거해 답한다.
- 한 번에 한 가지만 질문해 사용자의 부담을 줄인다.
- 정중하고 간결한 존댓말로 답한다.

## 플랫폼 추천 기준 (Platform_Rule 참고)
- 공개·내부 데이터 + 개인·소수 사용 → Agent Builder
- 대외비 이상 또는 사내 시스템 연동·승인 필요 → Copilot Studio

## 설계서 출력 형식
다음 항목을 표로 정리해 제시한다.
1. 에이전트 이름과 한 줄 목적
2. 추천 플랫폼과 선정 이유
3. 안내(Instructions) 초안
4. 필요한 지식(Knowledge Source) 목록
5. 테스트 시나리오 3개
6. 보안 체크리스트 확인 결과
💡
핵심: 목적·대화 방식·가이드라인·출력 형식을 명확히 나눌수록 응답 품질이 올라갑니다. 특히 분기 질문을 구체적으로 적어두면 에이전트가 빠뜨림 없이 인터뷰합니다. 모호한 지시 → 모호한 응답.
PART 2 2.3 · 지식 추가

지식 추가

지식 원본 선택

구성 탭의 지식 영역은 “에이전트가 응답을 생성하는 데 사용할 원본”을 등록하는 곳입니다. 파일, 모임, 채팅, 이메일 및 웹 사이트 추가에서 원본을 고릅니다.

실습 문서 업로드

  • 파일 업로드: 내려받은 Security_Rule.docx 등 4종 파일을 입력창에 끌어다 놓거나 업로드 아이콘으로 추가

  • 모든 웹 사이트를 검색합니다: 공개 웹 검색 토글 / 지정된 원본만 사용: 등록 자료만 근거로 답하게 제한

업로드하면 업로드된 파일 목록에 표시되고, 잠시 준비 중 상태를 거쳐 사용 가능해집니다.

SharePoint 파일최대 100개
OneDrive 파일최대 50개
공개 웹사이트 URL최대 4개 (2단계 이하)
전체 지식 원본(합계)최대 20개
⚠️
관리자가 웹 검색 정책을 끈 경우, 화면의 “모든 웹 사이트를 검색합니다” 토글이 켜져 있어도 웹 검색이 동작하지 않습니다.
PART 2 2.4 · 기능·추천 프롬프트

기능·추천 프롬프트

기능 토글 켜기

  • 문서, 차트 및 코드 만들기: ON (데이터 분석·Word·Excel·PowerPoint 파일 생성 — 설계서 생성에 필요)
  • 이미지 만들기: 시각 자료 생성 (선택)
📄
Word 결과물, 항상 자동은 아닙니다: 문서, 차트 및 코드 만들기를 켜면 에이전트가 Word·Excel·PowerPoint 파일을 만들 수 있습니다. 다만 ① 이 기능이 켜져 있고 ② 사용자가 “Word 문서로 만들어 줘”처럼 요청할 때만 생성되며, 서식은 가벼운 편입니다(매번 동일하지 않음). 매번 같은 형식의 정식 설계서가 필요하면 PART 3의 Copilot Studio(전용 Tool)로 만듭니다.

추천 프롬프트(Starter Prompts) 3개 등록

추천 프롬프트는 사용자(구성원)가 첫 화면에서 클릭해 에이전트에게 보내는 말입니다. 그래서 코치의 질문이 아니라 사용자 입장의 문장으로 적습니다. 각 프롬프트는 제목과 메시지를 함께 입력합니다.

①
제목내 업무 고충 말하기
메시지회의록 정리에 매주 몇 시간씩 쓰고 있어요. 이 업무를 도와줄 에이전트를 만들 수 있을까요?
②
제목플랫폼 추천받기
메시지제 업무와 다루는 데이터를 알려드릴게요. Agent Builder와 Copilot Studio 중 무엇이 적합한지 추천해 주세요.
③
제목제작 설계서 받기
메시지앞에서 이야기한 업무에 맞는 에이전트의 제작 설계서를 목적·지식·테스트 시나리오까지 정리해 Word 문서로 만들어 주세요.
PART 2 2.5 · 테스트·생성·공유

테스트 · 생성 · 공유

사용해 보기로 검증

오른쪽 사용해 보기 탭에서 추천 프롬프트를 눌러 대화해 봅니다. (이름·설명·안내가 채워지면 활성화) “매주 보고서 작성에 4시간씩 써요” 같은 입력으로 응답을 확인합니다.

만들기로 생성

우측 상단 만들기를 클릭합니다. 생성 직후에는 “비공개(나만 사용 가능)” 상태입니다.

공유(Share)로 공유 범위 설정

  • 나만(Only you): 작성자만(기본)
  • 특정 사용자(Specific people): 지정 사용자·보안 그룹·팀
  • 조직의 모든 사용자(Anyone in your org): 조직 전체
✅
여기까지 완료하면 5~10분 만에 동작하는 A4A Lite가 완성됩니다. 정식 운영은 PART 3의 Copilot Studio로 확장합니다.
PART 3 Copilot Studio 핸즈온

풀버전 A4A 구현: 실습 개요

Microsoft Copilot Studio(구 Power Virtual Agents)로 Knowledge 그라운딩, Tools, Topics, 생성형 오케스트레이션, 그리고 사람의 승인(HITL)까지 갖춘 본격 에이전트를 만듭니다.

🧭
PART 2에서 노코드로 가볍게 만든 A4A를, 이번엔 실제 업무에 쓸 수 있는 수준으로 끌어올립니다. 같은 A4A지만, 인터뷰 흐름(Topic), 사내 지식 연결(Knowledge), 설계서 생성 도구(Tools), 담당자 승인(HITL)까지 갖춰 “제대로 동작하는 제작 코치”를 완성합니다.

이 실습을 마치면

  • Copilot Studio에서 에이전트를 생성하고 Knowledge 4종을 등록할 수 있습니다
  • 인터뷰용 Topic과 설계서 생성용 Tool(프롬프트/플로우)을 만들 수 있습니다
  • 생성형 오케스트레이션을 이해하고 Test 후 Publish할 수 있습니다
📝
용어 안내: 이 도구는 더 이상 “Power Virtual Agents”가 아닌 Copilot Studio이며, 예전의 Actions/Plugins는 모두 Tools로 통합되었습니다. 챗봇은 에이전트(Agent)로 부릅니다.
PART 3 3.1 · 에이전트 생성

에이전트 생성

Copilot Studio 접속

브라우저에서 copilotstudio.microsoft.com 에 접속합니다. 홈 화면에 “에이전트가 무엇을 하길 원하는지 설명하세요” 자연어 입력 상자가 보입니다.

빈 에이전트로 시작

정확한 학습을 위해 자연어 생성 대신 직접 만듭니다. 홈의 Create an agent 또는 Agents 페이지에서 Create blank agent를 선택합니다.

기본 정보 입력

  • Name : A4A 제작 코치 (최대 42자, < > 불가)
  • Description : 에이전트 용도 한 줄 (최대 1,024자)
  • Instructions : PART 2의 안내 프롬프트 재사용 (최대 8,000자)

생성 후 Overview 페이지가 열립니다.

🧭
에이전트 좌측 메뉴: Overview · Knowledge · Topics · Tools · Agents · Activity/Analytics · Channels · Settings. 상단에는 Test·Publish 버튼이 있습니다.
PART 3 3.2 · Knowledge 추가

Knowledge 추가: 사내 4종 그라운딩

Add knowledge 열기

좌측 Knowledge → Add knowledge를 선택합니다.

원본 유형 선택 후 4종 등록

아래 유형 중 하나로 실습 문서를 올립니다.

  • Documents: Security_Rule 등 4종 파일 업로드(Dataverse 저장)
  • SharePoint: 사내 사이트 URL (Graph 검색, Entra 인증 필요)
  • Public website: 공개 도메인
  • Dataverse: 테이블 직접 연결(고급)

이름·설명 정리

각 지식 원본의 Description을 구체적으로 작성합니다. 생성형 오케스트레이션이 이 설명을 보고 어떤 자료를 검색할지 결정합니다.

💡
Work IQ 토글을 켜면 M365 시맨틱 인덱스로 SharePoint 검색 품질이 크게 향상됩니다. (에이전트 인증이 Authenticate with Microsoft일 때)
PART 3 3.3 · 생성형 오케스트레이션

생성형 오케스트레이션 확인

Settings → Generative AI

좌측 Settings → Generative AI에서 “Use generative AI orchestration…”이 Yes인지 확인합니다(신규 에이전트 기본값).

  • 생성형(ON): 토픽·도구·지식을 자동 선택, 트리거 문구 불필요(Description 기반)
  • 클래식(OFF): 토픽마다 트리거 문구 5~10개로 매칭

Allow ungrounded responses 검토

같은 화면에서 이 토글을 OFF로 두면, 지식·도구에 근거하지 않은 답변을 차단해 환각을 줄일 수 있습니다.

PART 3 3.4 · 인터뷰 Topic

인터뷰 Topic 만들기: Pain-point 수집

새 토픽 생성

좌측 Topics → Add a topic → From blank. 빈 캔버스에 Trigger 노드가 나타납니다.

트리거 설정

  • 생성형 모드: Trigger가 “The agent chooses”로 표시됩니다. 토픽 Description에 “사용자의 업무 고충을 인터뷰로 구체화한다”처럼 명확히 적습니다.
  • 클래식 모드: Trigger의 ... → Properties → Phrases에 “업무가 힘들어요”, “자동화하고 싶어요” 등 5~10개 입력.

질문 노드 추가

+ (Add node) → Question으로 분기 질문을 추가하고, 답변을 변수(예: painPoints)에 저장합니다.

  • “어떤 업무가 가장 반복적인가요?”
  • “그 업무에서 주로 어떤 데이터를 참조하나요?”
  • “결과물은 어떤 형태(보고서·메일 등)인가요?”

지식 기반 답변

마지막에 + → Advanced → Generative answers 노드를 추가하면, 등록한 Knowledge 4종을 검색해 사내 규정에 맞는 설계 방향을 답합니다.

PART 3 3.5 · 설계서 생성 Tool

설계서 생성 Tool 추가

Tools 페이지에서 도구 추가

좌측 Tools → Add a tool → New tool. 도구 유형을 고릅니다.

도구 유형용도
Prompt단일 LLM 프롬프트, 인터뷰 결과를 설계서 형식으로 구조화
Agent flow로우코드 자동화, Word 생성·SharePoint 업로드·승인
Custom connector외부 API/서비스 연결
MCPModel Context Protocol 서버 연결(신규)

Prompt 도구로 설계서 구조화

New tool → Prompt를 선택하면 프롬프트 편집기가 열립니다. 인터뷰 변수(painPoints 등)를 입력으로 받아 “지침·토픽·지식 매핑·테스트 시나리오” 형식의 설계서를 생성하도록 작성하고 Test로 확인합니다.

(선택) Agent flow로 Word·승인 연결

좌측 Flows → New flow → Agent flow. 트리거 When an agent calls the flow, 마지막에 Respond to the agent가 있어야 하며 100초 내 응답·Publish 필수입니다.

  • Word 템플릿 채우기 → SharePoint 업로드
  • Human in the loop 액션으로 승인 요청(다음 단계)
PART 3 3.6 · 사람의 승인(HITL)

사람의 승인(HITL) 추가

승인 요청 단계 넣기

Agent flow의 Human in the loop 액션 범주에서 Approval 요청을 추가합니다. 설계서가 완성되면 담당자에게 Teams 승인/이메일로 검토를 요청합니다.

승인 후 재개

담당자가 승인하면 플로우가 재개되어 결과를 에이전트에 반환하고, 사용자에게 최종 설계서 링크를 전달합니다. (거절 시 수정 안내)

🙋
사람 상담사로의 전환이 필요하면 시스템 토픽 Escalate에 Topic Management → Transfer conversation 노드를 추가합니다.
PART 3 3.7 · 테스트·게시

테스트와 게시

Test your agent

상단 Test를 눌러 오른쪽 패널에서 대화합니다. 생성형 모드에서는 Activity map이 어떤 토픽·도구·지식이 선택됐는지 실시간으로 보여줍니다. 응답을 클릭하면 해당 노드로 이동합니다.

Publish

상단 Publish → 확인 → 게시 완료(수 분 소요).

Channels 연결

Channels에서 Teams and Microsoft 365 Copilot을 추가하면 사내에서 바로 사용할 수 있습니다. 조직 배포는 Submit for admin approval로 관리자 승인을 받습니다.

🎉
축하합니다! 인터뷰부터 설계서 생성·승인·게시까지 이어지는 풀버전 A4A를 완성했습니다.
